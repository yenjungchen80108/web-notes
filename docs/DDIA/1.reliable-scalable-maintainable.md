# 1. Reliable, Scalable, and Maintainable applications

## 3 concerns in software systems

1. **reliability**

The system should continue to work correctly even in the face of adversity

- a fault: a component of the system deviating from its spec
- a failure: when the system as a whole stops providing the required service

  ex. hardware faults, software errors, human errors

2. **scalability**

As the system grows, there should be reasonable ways of dealing with that growth

- latency: the duration that a request is waiting to be handled
- response time: besides the actual time to process the request, it includes network delays and queuing delays
- algos that can calculate a good approximation of percentiles at minimal cpu and memory cost, ex. forward decay, t-digest, hdrhistogram, etc.

> scaling up: vertical scaling

> scaling out: horizontal scaling

3. **maintainability**

The system should be easy to understand, modify, and extend

> 3 design principles: operability, simplicity, evolvability

- operability: the system should be easy to operate and monitor
- simplicity: the system should be easy to understand and modify
- evolvability: the system should be easy to extend and evolve

## 3 design principles

1. **operability**

Making life easy for operations engineers

- monitoring
- logging
- alerting
- debugging
- capacity planning
- configuration management
- etc.

2. **simplicity**

Managing complexity

One of the best tolls we have for removing accidental complexity is abstraction.
A good abstraction can hide a great deal of implementation detail behind a clean, simple-to-understand facade.

3. **evolvability**

Making change easy

Agile working patterns provide a framework for adapting to change. The agile community has also developed technical tools and patterns that are helpful when developing software in a frequently changing environment. Such as test-driven development, continuous integration, etc.
