# Browser event

## 當頁面關閉時要執行某些方法，該怎麼實作？

當你希望在使用者「關閉頁面、重新整理、或切換到其他頁面」時執行某些清理或儲存操作，可以透過 Page Lifecycle API 搭配傳統的 visibilitychange、beforeunload、pagehide 事件來實作。以下是完整解釋與範例。

✅ 一般做法：監聽 pagehide 或 beforeunload

這兩個事件最常用於處理「頁面關閉時」的邏輯。

✅ pagehide（推薦）

> pagehide 是比較現代的方式，可正確捕捉到「使用者關閉分頁」或「轉到其他頁面」的行為。

```js
window.addEventListener("pagehide", (event) => {
  console.log("Page is being hidden or unloaded");
  // 在這裡儲存使用者資料、清除資源等
});
```

✅ beforeunload（會出現提示視窗）

用於阻止頁面離開，或在離開前執行動作（不推薦複雜操作，某些瀏覽器會阻止）。

```js
window.addEventListener("beforeunload", (event) => {
  // event.preventDefault(); // 可選，會出現瀏覽器提示
  console.log("Page is about to unload");
  // 儲存狀態等
});
```

✅ 結合 Page Visibility API（頁面變成 background 時）

可偵測使用者切到其他分頁或最小化瀏覽器。

```js
document.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "hidden") {
    console.log("Page is hidden");
    // 儲存資料或暫停動畫等
  }
});
```

✅ 更進階：使用 Page Lifecycle API（非標準、僅 Chrome 支援）

Chrome 提供 page-lifecycle 事件，可偵測更詳細的頁面狀態，如 frozen（暫停執行）或 terminated（強制關閉）：

```js
document.addEventListener("freeze", () => {
  console.log("Page is being frozen");
  // 儲存狀態
});

document.addEventListener("resume", () => {
  console.log("Page is resumed from frozen");
});
```

> 但注意：這是非標準功能，只有部分瀏覽器（如 Chrome）支援。

✅ 實用範例：儲存表單草稿、上報最後動作、關閉 socket

```js
window.addEventListener("pagehide", () => {
  localStorage.setItem("draft", document.querySelector("#note").value);
  // 停止 socket 或 API 上報
});
```

✅ 小結：不同用途建議

| 事件名           | 何時觸發                                        | 用途                                                         |
| ---------------- | ----------------------------------------------- | ------------------------------------------------------------ |
| pagehide         | 離開頁面時，支援 bfcache 最安全處理 unload 行為 | beforeunload 即將離開，可中斷 提示使用者保存草稿（有副作用） |
| visibilitychange | 切到背景或最小化                                | 暫停音樂、儲存暫存資料                                       |
| freeze / resume  | Page Lifecycle API（Chrome）                    | 進階狀態管理                                                 |

## 使用者關閉瀏覽器前，如何發送尚未上傳的埋點資料？

當使用者關閉瀏覽器、關閉分頁或跳轉到其他網站前，你可以使用 **navigator.sendBeacon()** 或 **visibilitychange / pagehide** 事件來安全地上傳尚未送出的埋點資料。

以下是你可以參考的最佳實作方式（✅ 可在 Next.js、React 等 SPA 或傳統頁面中使用）：

✅ 推薦解法：使用 navigator.sendBeacon() 搭配 pagehide 事件

```js
window.addEventListener("pagehide", () => {
  const pendingLog = getPendingAnalytics(); // 從 localStorage / queue 中取出資料

  if (pendingLog.length > 0) {
    const blob = new Blob([JSON.stringify(pendingLog)], {
      type: "application/json",
    });
    navigator.sendBeacon("/api/analytics", blob);
  }
});
```

🔍 為何用 pagehide 而不是 beforeunload？

- pagehide 專為頁面即將凍結、快取（如 BFCache）或卸載前觸發
- 更穩定，不會被瀏覽器忽略（Safari 對 beforeunload 支援較差）

✳️ 備用方案：beforeunload + sendBeacon（⚠ 有風險）

```js
window.addEventListener("beforeunload", () => {
  const log = getPendingAnalytics();
  const blob = new Blob([JSON.stringify(log)], { type: "application/json" });
  navigator.sendBeacon("/api/analytics", blob);
});
```

📛 缺點：某些瀏覽器會忽略這段（如 Safari），且 beforeunload 不能有 async/await，不適合 fetch。

✅ 加強：與 localStorage 暫存結合

為避免資料遺失，可搭配 localStorage 暫存：

```js
function queueAnalytics(event) {
  const current = JSON.parse(localStorage.getItem("pendingEvents") || "[]");
  current.push(event);
  localStorage.setItem("pendingEvents", JSON.stringify(current));
}

function getPendingAnalytics() {
  const data = JSON.parse(localStorage.getItem("pendingEvents") || "[]");
  localStorage.removeItem("pendingEvents");
  return data;
}
```

🚀 實務應用建議

| 機制                  | 適合情境                             |
| --------------------- | ------------------------------------ |
| sendBeacon + pagehide | 離開頁面、返回上一頁（SPA 頁面跳轉） |
| localStorage 暫存     | 使用者太快關頁導致資料來不及送出     |
| visibilitychange      | 使用者切出頁面、隱藏頁籤時           |

⸻

🔚 小結

| 技術           | 是否阻塞關閉？ | 是否保證送出？ | 瀏覽器支援                    |
| -------------- | -------------- | -------------- | ----------------------------- |
| sendBeacon     | ❌ 非阻塞      | ✅ 高成功率    | Chrome, Firefox, Edge, Safari |
| fetch          | ❌ 非阻塞      | ⚠ 成功率低     | 部分支援 keepalive            |
| XMLHttpRequest | ⚠ 阻塞但不推薦 | ⚠ 老舊不穩定   | 老瀏覽器                      |

## 請解釋 navigator.sendBeacon 方法的用途

navigator.sendBeacon() 是一個用來 **在頁面卸載（unload）或關閉之前，安全地將少量資料傳送到伺服器** 的方法，通常用於 **統計追蹤、記錄使用者行為、錯誤回報等背景任務**。

🔧 基本用途

```js
navigator.sendBeacon(url, data);
```

- url：伺服器接收資料的位址
- data：要傳送的資料（通常是 Blob, ArrayBufferView, FormData, URLSearchParams, 或 string）

🧠 它解決了什麼問題？

傳統問題：用 AJAX 傳資料，在頁面卸載時常常會失敗

例如：

```js
window.addEventListener("beforeunload", () => {
  fetch("/log", {
    method: "POST",
    body: JSON.stringify({ page: "home" }),
    keepalive: true, // 有支援但不穩定
  });
});
```

這種寫法有兩個問題：

1. 使用者離開頁面太快時，資料來不及送出
2. 某些瀏覽器限制 fetch 時間，或根本不保證會送出

✅ sendBeacon 的優點

| 優點                         | 說明                                       |
| ---------------------------- | ------------------------------------------ |
| 非同步且非阻塞               | 不會卡住 UI 或延遲頁面關閉                 |
| 在頁面 unload 時也能保證送出 | 專門設計給這種情境                         |
| 傳輸安全穩定                 | 瀏覽器會盡力把資料送出，即使在 unload 階段 |

🧪 實際使用情境

1. 使用者離開頁面前，上報統計資料

```js
window.addEventListener("unload", () => {
  const data = new Blob(
    [JSON.stringify({ event: "exit", page: location.pathname })],
    {
      type: "application/json",
    }
  );
  navigator.sendBeacon("/analytics/track", data);
});
```

2. 錯誤追蹤服務（如 Sentry）收集錯誤事件

```js
window.addEventListener("error", (e) => {
  const errorData = JSON.stringify({
    message: e.message,
    url: e.filename,
    line: e.lineno,
  });
  navigator.sendBeacon("/log/error", errorData);
});
```

🚫 限制與注意事項

| 限制                       | 說明                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| ❌ 無法取得伺服器回應      | 沒有 then()、無法處理 response                                    |
| ❌ 資料量限制              | 通常在數十 KB 內較穩定（依瀏覽器而異）                            |
| ❌ 只支援 POST 方法        | 並且 Content-Type 通常會是 text/plain 或 application/octet-stream |
| ❌ 跨網域可能需要設定 CORS | 否則預設會被阻擋                                                  |

🔚 結論

navigator.sendBeacon() 是在頁面即將離開時「最後一刻」傳送小量資料的最佳方式，適合用在：

- 使用者行為追蹤
- 離線紀錄上傳
- 錯誤回報

它不是用來做主流程的資料操作（例如讀寫資料庫、API 回應處理），但非常適合背景性質的資料投遞。
