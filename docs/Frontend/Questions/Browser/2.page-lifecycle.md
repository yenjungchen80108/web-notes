# Page lifecycle

## Page Lifecycle API 狀態圖

<img src="/img/FE/page-lifecycle-api-state.svg" width="100%" height="100%" alt="Logo" />

這張圖是 Page Lifecycle API 的狀態圖，描述了瀏覽器中一個網頁的生命週期狀態轉換，特別是和 cache（回前進快取 / bfcache）有關的流程。

🔁 什麼是 bfcache？

bfcache（Back/Forward Cache）是一種讓瀏覽器在使用者點擊「上一頁」或「下一頁」時，**可以瞬間還原頁面狀態**的快取機制。這讓你返回前一頁的速度非常快，**因為整個頁面並沒有被重新載入，而是被「凍結（frozen）」起來，再「恢復（resume）」**。

🧠 bfcache 的流程重點（看圖的右半部）

1. 🚪 pagehide 事件觸發時（流程 i）

當使用者離開頁面（例如點擊上一頁），會觸發 pagehide 事件。

2. ❓ event.persisted 判斷是否進入 bfcache

pagehide 中的 event.persisted 屬性會告訴你：

- true：頁面被保留在 bfcache 中（會進入 FROZEN 狀態）
- false：頁面會被完全卸載，走 unload → TERMINATED

3. 🧊 如果符合快取條件，會進入 FROZEN 狀態（流程 j → k）

頁面會進入「凍結」狀態，JS 不再執行，但狀態還保留（例如你輸入的表單資料、滾動位置）。

4. 🔁 使用者點返回鍵 → pageshow 觸發（流程 n）

頁面從 FROZEN 狀態喚醒，恢復至 ACTIVE 或 PASSIVE，並觸發 pageshow 事件。
可透過 event.persisted === true 判斷是否從快取回來。

5. 🗑 若符合 discard 條件（如記憶體壓力），會被丟棄（DISCARDED）

頁面在 bfcache 中可能會被清除。下一次載入時 document.wasDiscarded === true。

⸻

✅ 實務開發：如何處理 bfcache

你可以使用這些事件判斷快取狀態並做資料保存或清除：

```js
window.addEventListener("pagehide", (event) => {
  if (event.persisted) {
    console.log("✅ 頁面進入 bfcache，保留狀態");
  } else {
    console.log("❌ 頁面即將卸載，不會快取");
  }
});

window.addEventListener("pageshow", (event) => {
  if (event.persisted) {
    console.log("♻️ 頁面從 bfcache 恢復");
  } else {
    console.log("🆕 頁面是正常載入");
  }
});
```

⚠️ 哪些頁面不能進 bfcache？

以下情況會導致無法被快取：

- 設定 unload 事件（使用 beforeunload 可以，但 unload 不行）
- 使用 WebSocket / WebRTC
- 網頁內含 `<iframe>` 且來源跨域
- 使用 document.cookie 做同步存取但未加快取策略
- 特定 HTTP 標頭（如 Cache-Control: no-store）

總結

這張圖右側重點說明了：

- pagehide ➝ 判斷是否進入 bfcache
- 若快取 ➝ FROZEN ➝ pageshow 恢復
- 若不快取 ➝ unload ➝ TERMINATED

你可以利用 pageshow 與 pagehide，配合 event.persisted 來安全處理前進後退快取情境，避免不必要的重載或錯誤邏輯。

## 為什麼在 Next.js 裡按「上一頁」，也能記住 In-App 的 Routing？

是的，這其實是 **瀏覽器的歷史堆疊（History Stack）** 在發揮作用，而不是 bfcache。

✅ 行為解析

當你在 Next.js 中使用：

```js
router.push("/detail");
```

這會觸發：

- Next.js 內部的「client-side routing」
- 不會重新載入頁面
- 但會使用 history.pushState() 把 /detail 加進瀏覽器的歷史紀錄

所以當你按「上一頁」，瀏覽器會觸發：

- popstate 事件

而 Next.js 的 router 會監聽這個事件，並自行處理路由還原（例如回到 /list），載入該頁的 component（通常是 dynamic import），但這一切都仍發生在：

💡 同一個 Document / SPA session 裡面

✅ 所以你按返回鍵時：

- 不是「瀏覽器重載」
- 不會觸發 pageshow, pagehide, unload
- 也不會觸發 bfcache 快取或還原
- 是 Next Router 幫你「在前端控制邏輯 + 觸發 component 切換」

也就是說：

| 行為                     | 本質                             | 控制者                  |
| ------------------------ | -------------------------------- | ----------------------- |
| router.push()            | history.pushState() + UI 切換    | Next.js Router          |
| 按返回鍵回上一頁         | 觸發 popstate → Next Router 處理 | 瀏覽器 + Next.js Router |
| 網頁整頁跳轉（重新載入） | 完整 HTTP 請求 + 新 Document     | 瀏覽器                  |
| 使用 bfcache 快取頁面    | 整頁快照保留                     | 瀏覽器引擎（不可控）    |

🧠 總結重點

即使是在 SPA（如 Next.js）裡面進行路由切換，只要使用了 history.pushState()（也就是 router.push() 背後的機制），瀏覽器還是會記住歷史紀錄，讓你能按「上一頁」回到上一個 client-side route。

- 是「SPA + History API」的組合
- 並不是 bfcache，也不是頁面重新載入
- 畫面不會白，是因為沒換 document，仍在 React 控制之中

🎯 延伸技巧

你可以這樣監聽 popstate：

```js
useEffect(() => {
  const onPopState = (e) => {
    console.log("使用者按了上一頁或下一頁");
  };
  window.addEventListener("popstate", onPopState);
  return () => window.removeEventListener("popstate", onPopState);
}, []);
```
